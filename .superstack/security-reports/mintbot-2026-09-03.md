## Attack-surface review

- HyperEVM RPC environment variables are selected only for chain ID `999`; startup verifies both WSS and every usable HTTP provider report the configured chain.
- Non-loopback RPCs require encrypted `https://` and `wss://` transport. RPC errors redact credential-bearing URLs and wallet addresses.
- OpenSea drop slugs are character-restricted before URL construction. API responses are size-bounded and untrusted text is sanitized.
- OpenSea transaction data is accepted only when it targets the canonical SeaDrop address. Calldata is ABI-decoded and bound to the configured NFT contract, wallet, quantity, and payable value.
- Final signing revalidates sender, chain ID, target, calldata, value, gas limit, gas-cost cap, nonce, and transaction field shape.
- The real `.env` is ignored by Git and has Unix mode `0600`. No secret values were printed during the audit.

## Residual operational risks

1. No live mint transaction was submitted during this audit. Validate a real collection and active OpenSea stage with `simulate` before funding a production run.
2. Aggressive mode intentionally skips trigger-time gas simulation and the final balance RPC. Use normal mode until a safe gas limit has been measured for the exact drop path.
3. Configure at least one independent HTTPS backup/broadcast RPC when reliability matters; every configured endpoint is chain-checked before use.
4. Use `expected_contract_code_hash` when a separately verified collection bytecode hash is available. Proxy implementation changes require separate verification.
5. The prior report's historical Git author-email and old-path privacy residue remains outside this diff audit; removing it still requires an explicitly authorized history rewrite.
